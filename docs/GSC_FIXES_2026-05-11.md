## Code Audit Findings

### 1. English-only canonical pages

These pages exist only in English:

- `/genosys`
- `/documents`
- `/guides`
- `/guides/*`

The sitemap already treated these as single-locale entries, but the proxy could still redirect direct requests like `/documents` or `/genosys` to `/ar/documents` or `/ru/genosys` when `NEXT_LOCALE` or `Accept-Language` preferred Arabic/Russian. Stale localized variants such as `/ar/documents` and `/ru/guides/...` would also reach non-existent routes.

### 2. Robots file duplication

A previous quick pass duplicated the `Googlebot`, `Google-Extended`, and `GoogleOther` groups near the top of `robots.txt`. Duplicate groups are not a useful crawl-budget optimization and make the file harder to reason about.

### 3. Sitemap route coverage

The localized sitemap entries for core public pages have matching routes. Product, concern, category, location, and blog dynamic routes also have EN/AR/RU page implementations. The English-only page list is now explicit and uses the existing single-locale helper.

## Fixes Implemented

### Proxy canonicalization

`proxy.ts` now handles English-only pages deterministically:

- Requests for `/genosys`, `/documents`, `/guides`, and `/guides/*` are served as English canonical URLs regardless of locale cookie or `Accept-Language`.
- Stale localized variants such as `/ar/documents`, `/ru/genosys`, and `/ar/guides/korean-skincare-dubai` redirect with `308` to the real English canonical path.

This directly addresses likely stale 404s and prevents the proxy from manufacturing non-existent localized URLs for English-only content.

### Sitemap clarity

`app/sitemap.ts` keeps English-only pages in a dedicated list and emits them through `singleLocaleUrl()` with no `alternates` object. This prevents accidental future addition of non-existent hreflang variants.

### Robots cleanup

`public/robots.txt` now keeps sitemap declarations near the top but removes the duplicated Google-specific groups from the earlier quick pass. The original specific bot sections remain later in the file.

## What This Does Not Claim

This does not prove that all 183 "Discovered - currently not indexed" URLs are fixed. That bucket often contains normal crawl backlog, duplicate/low-value pages, or URLs discovered from feeds/internal links that Google has not prioritized yet.

This also does not prove that all 56 "Crawled - currently not indexed" URLs are fixed. That bucket usually requires URL-level review for content quality, duplication, canonical choice, and rendered HTML.

## Required GSC Follow-Up

Export URL samples from each issue bucket and classify them:

1. `Not found (404)` - verify each URL now returns either `200`, `301/308` to a valid canonical, or intentional `404`.
2. `Soft 404` - inspect the rendered content and make the page either useful/indexable or explicitly `noindex`/redirect.
3. `Duplicate, Google chose different canonical` - compare declared canonical, hreflang, internal links, and sitemap inclusion.
4. `Crawled - currently not indexed` - check whether pages are thin, duplicated, blocked by canonicalization, or missing internal links.
5. `Discovered - currently not indexed` - separate normal crawl queue from stale/bad URLs.
