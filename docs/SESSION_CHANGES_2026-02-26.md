# Session Changes — February 26, 2026

## App Store Download Button on Login Page

### Summary

Added a **"Download Genosys UAE App"** button on the login page (website and mobile web) to promote the native iOS app. The button appears below the "Sign in with Apple" button and above the "OR" divider on all login views.

### What Changed

| File | Change |
|------|--------|
| `app/login/LoginClient.tsx` | Added App Store download button in **mobile web** view (full-width, below Google/Apple row) and **desktop** view (below Sign in with Apple) |
| `components/LoginModal.tsx` | Added App Store download button in **login modal** (below Sign in with Apple) |
| `messages/en.json` | Added `login.downloadApp`: "Download Genosys UAE App" |
| `messages/ru.json` | Added `login.downloadApp`: "Скачать приложение Genosys UAE" |
| `messages/ar.json` | Added `login.downloadApp`: "تحميل تطبيق Genosys UAE" |

### Button Specification

| Property | Value |
|----------|-------|
| Text | "Download Genosys UAE App" (translated EN/RU/AR) |
| Translation key | `login.downloadApp` |
| Link | https://apps.apple.com/ae/app/genosys-uae/id6756648064 |
| Target | `_blank` (new tab) with `rel="noopener noreferrer"` |
| Style | Black background, white text, Apple logo icon |
| Element | `<a>` tag (not `<button>`) since it's a navigation link |
| RTL support | Yes — `flex-row-reverse` when `dir === 'rtl'` |

### Where It Appears

| View | Location | Styling Notes |
|------|----------|---------------|
| **Desktop** (`LoginClient.tsx`) | Below "Sign in with Apple", above "OR" divider | `rounded-lg`, matches auth button width, slightly smaller padding (`py-2`) |
| **Mobile Web** (`LoginClient.tsx`) | Full-width below the Google/Apple button row, above "OR" divider | `rounded-xl`, `py-3`, consistent with mobile design |
| **Login Modal** (`LoginModal.tsx`) | Below "Sign in with Apple", above "OR" divider | `rounded-system`, uses elevation classes, `min-h-[44px]` touch target |

### Not Affected

- **Native iOS app** (`genosys-mobile-app`) — has its own separate codebase, no changes made
- **PWA login** — shares the same `LoginClient.tsx`, so the button appears there too (acceptable since PWA users may want to switch to native)

```
│     Sign in with Apple      │  ← black, auth action

├─────────────────────────────┤

```

## Remove "Generate Link for Payment" Option & Rename "Stripe Checkout" to "Card Payment"

### Summary

Removed the **"Generate Link for Payment"** (support-link) payment method from the checkout UI across all views (desktop, mobile web, PWA). Payment links will no longer be generated manually by the support team. Renamed **"Stripe Checkout"** to **"Card Payment"** for clarity. Updated all customer-facing text including FAQ answers, chatbot knowledge, and order history labels in all three languages (EN, AR, RU).

### What Changed

| File | Change |
|------|--------|
| `components/checkout/PaymentMethodSelector.tsx` | Removed support-link button (mobile) and radio option (desktop). Removed blue info box about support team payment links. Renamed "Stripe Checkout" → `t('checkout.cardPayment')`. Mobile button label "Online" → "Card" / "بطاقة" / "Картой". Removed unused `Building` import. |
| `app/checkout/CheckoutClient.tsx` | Removed `'support-link'` from allowed payment methods. Commented out entire support-link handling block (~120 lines) with condensed reference. |
| `app/orders/page.tsx` | Simplified payment method display: any non-COD order now shows "Card/Apple Pay" (removed separate "Payment Link" label for old support-link orders). |
| `lib/chatbot/config.ts` | Updated blog post #4 description from "Stripe payments, Apple Pay, Google Pay, Link integration" → "Card payment online (Visa, Mastercard, Apple Pay, Google Pay) and Cash on Delivery". |
| `messages/en.json` | Added `checkout.cardPayment`: "Card Payment". Updated `checkout.paymentDescription` (removed payment link mention). Updated `faq.questions.paymentMethods.a` (removed "link is generated by our support team"). |
| `messages/ar.json` | Added `checkout.cardPayment`: "الدفع بالبطاقة". Updated `checkout.paymentDescription` and `faq.questions.paymentMethods.a` accordingly. |
| `messages/ru.json` | Added `checkout.cardPayment`: "Оплата картой". Updated `checkout.paymentDescription` and `faq.questions.paymentMethods.a` accordingly. |

### Payment Methods — Before vs After

| | Before | After |
|---|--------|-------|
| **Desktop** | 3 radio options: Stripe Checkout, Cash on Delivery, Generate Link for Payment | 2 radio options: Card Payment, Cash on Delivery |
| **Mobile/PWA** | 3 toggle buttons: Cash, Online, Link | 2 toggle buttons: Cash, Card |
| **FAQ answer** | "...The link for payment is generated by our support team once the order is placed." | "We accept two payment methods: Card Payment online (Visa, Mastercard, Apple Pay, Google Pay) and Cash on Delivery (COD)." |

### New Translation Keys

| Key | EN | AR | RU |
|-----|----|----|-----|
| `checkout.cardPayment` | Card Payment | الدفع بالبطاقة | Оплата картой |

### What Was NOT Changed (Intentionally Preserved)

- **`/api/orders/support-link/route.ts`** — Backend API still exists (not reachable from UI)
- **`/api/send-sample-support-link/route.ts`** — Internal test endpoint
- **`app/success/SuccessClient.tsx`** — Still handles support-link success page for old orders
- **`app/template/page.tsx`** — Email template preview (has support-link case)
- **`services/orders.ts`** — `submitSupportLinkOrder()` function (unused, harmless)
- **Email templates** (`lib/email/`) — Needed for old support-link order emails
- **Old translation keys** (`generateLinkForPayment`, `supportTeamWillShareLink`) — Kept for backward compat
