# Баг-репорт для разработчиков МойСклад — экспорт отчёта по товарам на комиссии

**Дата:** 03.07.2026
**Аккаунт:** Genosys Middle East FZ-LLC
**Приоритет:** средний (данные в системе корректны, ломается печать/выгрузка)

---

## Кратко

Кастомный шаблон печати «Goods on Consignment Report» (отчёт по остаткам
переданных на комиссию товаров) даёт **разный результат** при печати из
веб-интерфейса и при выгрузке через JSON API. Через API возвращается **пустой
документ**. Кроме того, расчёт остатка в отчёте **завышает количество**, так как
складские отгрузки-«зачёты» (мирроры к отчётам комиссионера) учитываются как
поступление товара.

---

## Проблема 1 — API-экспорт возвращает пустой документ

### Как воспроизвести

1. Договор комиссии `00060` (контрагент «Serene Skin Beauty Salon LLC»).
2. Кастомный шаблон печати `Invoice_Consignment_Report_Genosys`
   (`customtemplate`, тип сущности `commissionreportin`).
3. Запрос:

```
POST /api/remap/1.2/entity/contract/{contractId}/export
Content-Type: application/json

{
  "template": {
    "meta": {
      "href": ".../entity/commissionreportin/metadata/customtemplate/{templateId}",
      "type": "customtemplate",
      "mediaType": "application/json"
    }
  },
  "extension": "pdf"
}
```

### Ожидаемо
PDF с реквизитами покупателя и позициями остатка (как при печати из UI —
~31 строка, шапка с контрагентом, итог по сумме).

### Фактически
- HTTP `303`, редирект на файл, PDF `59 416 байт`.
- Содержимое **пустое**: `Dated 12.04.2023` (дата создания договора),
  блок покупателя пуст, таблица позиций пуста, `TOTAL AED 0,00`.
- Тот же шаблон, распечатанный **из веб-интерфейса**, формируется полностью и
  корректно по составу строк.

### Вывод
Data-provider шаблона при выгрузке через API по сущности `contract`
**не получает** данные об остатках на комиссии, которые доступны при печати из UI.
Поведение UI-печати и API-экспорта должно совпадать.

## Проблема 2 — Завышение остатка в отчёте по комиссии

### Симптом
Для того же договора `00060` печатный отчёт показывает остатки **больше**
фактических:

| Товар | Отчёт МойСклад | Факт (пересчёт на точке) |
|-------|---------------:|-------------------------:|
| Snow O₂ Cleanser 180ml | 4 | 3 |
| Intensive Problem Control Cream | 3 | 2 |
| Intensive Blemish Balm Cream | 2 | 1 |
| Multi Sun Cream SPF40 | 3 | 1 |
| BB Cushion #2 Beige | 3 | 2 |
| Moisture Replenishing Hyaluron Serum | 1 | 0 |
| Ultra Shield SPF50 | 2 | 1 |
| **Итого по документу** | **9 853 AED / 31 строка** | **6 747 AED / 25 строк** |

### Причина
Остаток в отчёте считается как `Σ отгрузок − Σ отчётов комиссионера`. При
взаиморасчётах в аккаунте исторически создавались **парные документы**: отчёт
комиссионера (продажа) + **зеркальная отгрузка** на те же позиции. Эти
отгрузки-«зачёты» (например, `06271`, `06436`) прибавляют товар обратно в остаток,
хотя физического поступления на точку не было.

### Запрос к разработке
1. Уточнить/задокументировать формулу остатка в отчёте по комиссии: какие типы
   документов и в каком знаке учитываются.
2. Рассмотреть механизм пометки/связки взаимозачётных отгрузок, чтобы они
   **не увеличивали** комиссионный остаток (или отдельный тип операции для
   зачёта, не влияющий на «переданные комиссионеру»).

*Примечание: проблема 2 частично связана со схемой ввода документов на нашей
стороне. Главный технический баг — проблема 1 (расхождение UI-печати и API-экспорта).*
